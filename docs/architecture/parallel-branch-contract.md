# 并行分支与汇总契约（阶段 4）

## 分支边界

普通问句先识别意图，再按固定顺序返回 `definition`、`field`、`schema`、`lineage`、`query` 分项。一个问句命中多个认证意图时，最多 4 个工作线程并行执行；每个分项独立解析任务状态、重新取得服务端身份、调用工具并得到自己的 `status`、`message`、`rows`、`citations` 和 `sql`。检索是口径、字段、表结构和血缘分项的证据子步骤，不是单独的用户意图。

意图契约含 `exploration`；显式 `探索试算` / `非认证试算` 或清楚表达隔离探索执行的说法走独立探索路径，保留 `NON_CERTIFIED` 标记与沙箱权限，不与认证查询合并为同一分项或同一数值。LLM 分类结果不授予探索权限；缺少明确选择时先澄清，探索与认证意图混合时要求拆分。它不参与认证多意图并行。

## 汇总规则

| 情况 | 分项状态 | 总体处理 |
|---|---|---|
| 全部成功 | 各分项 `ok` | 总体 `ok`，按意图顺序展示 |
| 部分成功 | 成功分项 `ok`，失败分项保留自身状态 | 总体 `ok`，附部分失败提示；成功证据不丢失 |
| 分支抛出未处理异常 | 该分项 `unavailable`，无数值、SQL 和引用 | 其他分项继续返回；异常原文不进入响应 |
| 权限拒绝 | 该分项 `refused` | 不返回该分项数据或引用 |
| 数值需要补充日期 | 查询分项 `needs_clarification` | 已确认的口径和血缘继续返回 |
| 没有可发布数值 | 查询分项 `no_data` 或 `unavailable` | 不用其他日期或 REALTIME/FINAL 状态填补 |

总体引用只来自通过各分项校验的证据，按引用 ID 去重。总体 `ok` 表示至少一个分项成功，不能理解成所有请求都成功；调用方必须逐项读取 `sections[].status`。异步任务的 `intent_progress` 会在分项完成时更新，并在最终汇总校验后与最终分项状态对齐。

## 版本校验

认证指标分项返回 `ok` 前，必须含唯一的 `metric:<metric_id>` 引用，且其中的指标版本与更新时间都等于当前认证目录。该指标的 RAG 证据片段也必须匹配同一版本与更新时间。任一不符，只有该分项降为 `unavailable`，同时清空其行、SQL 和引用；其他版本一致的分项保留。

数值分项的 `batch:*` 引用描述实际数据批次和发布时间，它的 `version` 是来源批次，不应被误当成指标定义版本。数值与口径的绑定依据是各自的 `metric:<metric_id>` 引用；来源批次另行说明数值新鲜度。表结构可来自不同的受认证文档版本，不能套用“所有引用版本全相同”的规则。

会话只保存经最终汇总认可的分支任务状态。若新指标的查询分支故障，后续追问可沿用已成功口径分支确认的新指标，但不会恢复上一个指标的日期或维度。若没有可用分支，则清空本轮任务状态。

## 验证范围

自动化用例覆盖：口径与血缘并行、口径成功而血缘故障、口径成功而数值不可用、指标版本冲突、过期检索证据、取消后的迟到结果、异步分项进度，以及新指标部分失败后的多轮追问。测试使用本地合成数据和故障注入；外部 Elasticsearch、DeepSeek 和真实业务数据的联调不属于本阶段证据。
