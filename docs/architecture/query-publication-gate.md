# 查询与 FINAL 发布安全门（阶段 5）

此文档记录本地合成数据实现，不代表生产发布审批或企业身份认证已经接通。

## 认证查询边界

1. 服务端解析身份和角色；目录为每个指标/工具重新检查权限。请求体、会话记忆和缓存均不能授予权限。
2. 认证目录中的指标属于 `credit` 域；用户即使另有 `restricted` 域权限，认证信贷指标的 SQL 和批次引用仍只覆盖 `credit`。跨域指标必须先建立明确的认证目录条目与专属权限模型。
3. 查询由指标定义生成固定聚合模板，不接受任意自然语言 SQL。SQLGlot 将候选 SQL 与模板进行 AST 结构比对；执行连接只读、设置超时，只读取最多 `max_rows` 行。请求模型限制日期最多 93 个自然日、结果上限 500 行。
4. 工具调用后再次校验当前身份；审计写入失败时，不向调用方发布本次结果。认证查询和标记为 `NON_CERTIFIED` 的探索试算是两条隔离路径。

## FINAL 发布判定

离线写入在质量检查完成后将批次和 ADS 结果发布为 `FINAL`。查询时不能只相信 ADS 行上的 `FINAL` 标签：对查询范围内每个来源批次，重新检查 `ingestion_batch` 中同业务日期的 `FINAL` 状态，以及 `quality_check` 中申请笔数、通过笔数、贷款笔数、贷款余额、逾期余额、还款金额六项 `PASS`。缺批次、缺检查、非 `PASS` 或撤回发布均返回 `unavailable`，不返回数值、SQL 或引用；即使缓存曾命中，也先执行此校验。成功结果引用中包含来源批次、发布日期和发布状态。

`REALTIME` 不套用离线 FINAL 批次门，结果明确标注暂态，不用于正式报表。缺失业务日期会给出覆盖范围提示，不用实时值冒充 FINAL。

## 已验证与剩余风险

- 自动化用例验证了混合权限账号不会把受限域余额混入信贷指标、撤回发布后缓存不能继续返回 FINAL、质量检查缺失时不返回 FINAL，以及既有固定 SQL/只读/审计链路。
- 当前发布复核与 SQL 执行使用两个 SQLite 连接，极短并发窗口内若发布状态改变，二者不构成同一数据库快照。生产迁移应把发布状态、来源和数值读取绑定到同一事务快照，或使用带版本的不可变发布清单与查询水位。当前项目不能宣称已解决并发撤回的强一致性问题。
- 企业 SSO、真实权限目录、Doris 查询安全策略和真实批次发布审批仍属后续生产化适配，不在本阶段本地验收范围内。
