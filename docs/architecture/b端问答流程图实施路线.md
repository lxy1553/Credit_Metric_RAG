# B 端数据问答流程图实施路线

本路线以同目录的 `b端数据问答端到端流程图.png` 为目标蓝图。此图描述目标能力，并不代表每个节点都已在当前代码中落地。当前实现是单机、本地合成数据的学习/验证项目；不得把它表述成生产系统。

## 项目边界

- 当前项目只建设 B 端数据问答与受控指标服务：知识检索、指标口径/字段/血缘问答、认证指标查询、权限与审计、异步问答任务及评测。
- 报告生成明确不在当前项目范围内：不实现报告 Agent、报告模板编排、定时生成、报告审批或分发。后续作为独立的 Report Generation Agent 项目建设。
- 后续报告 Agent 如需使用本项目数据，应通过认证指标/数据服务接口获取带版本、数据状态和引用的结果；不直接复用本项目的会话状态或绕过权限访问底层数据。两个项目的认证、审计和发布边界分别负责，再通过明确的服务契约集成。

## 当前基线

- 初始测试基线：2026-10-10，101 项通过。
- DeepSeek 意图路由改动后：108 项通过；新增的 DeepSeek 协议测试使用本地 MockTransport，不访问外网。
- 意图评测工具与回归集加入后：112 项通过；唯一提示为既有 Starlette 弃用警告和受限环境无法写入 pytest 缓存，不影响测试结果。
- DeepSeek 真实联通烟测：使用合成问句“逾期率口径和血缘”，返回 `definition`、`lineage`；本地端到端 API 也返回口径与血缘两个成功分项，未发送客户数据。
- 24 条合成意图开发集在线对比：DeepSeek `deepseek-flash` exact match / micro-F1 均为 100%，5/5 闲聊与越界问题保持拒绝路由；本地确定性规则 exact match 为 83.3%（20/24），micro-F1 为 91.3%。本次 24 次调用 0 次失败，平均约 1.05 秒，成功请求 P95 约 1.64 秒。脱敏聚合结果见 `var/intent-routing-evaluation.json`；报告不含原始问题文本。
- 已具备：FastAPI 异步问答任务、request_id 状态轮询、任务级 metadata checkpoint、同用户重新提交恢复、受限意图并行、认证目录/RAG 引用、服务端身份授权、固定查询模板和 SQLGlot 校验、只读查询、REALTIME/FINAL 标记、非认证探索沙箱、审计与 Trace ID。
- 仍受限：本地内存线程池不是持久任务队列；SQLite checkpoint 不是分布式队列；恢复会重跑整条任务而非 LangGraph 节点级续跑；没有配置 LLM；Trace ID/审计不等于 LangSmith/OpenTelemetry 全链路 span；实时与 FINAL 批流差异对账尚未完整覆盖迟到、补数和 FINAL 发布标记；演示身份不等于企业 SSO。
- 安全边界：未经确认，不启用外部 LLM 发送信贷问题；不让模型决定授权，不执行任意自然语言 SQL；认证查询与非认证探索分开，探索结果不得混入 FINAL。
- 非认证 Vintage 探索新增本地验收：候选目录绑定固定来源字段与模板；仅分析员、显式 opt-in；接受 YYYYMM / YYYY-MM / 完整日期；只读单月末合成快照，输出 cohort × MOB、分子分母、草稿版本/更新时间和来源引用；SQLGlot 限定单一沙箱表，内存只读执行、1000 源行/100 结果行上限并写审计。此实现用于验证规则，不代表生产数据接通或认证口径发布。

## 八个实施阶段

| 阶段 | 目标 | 完成标准 |
|---|---|---|
| 1 | 可选 LLM 意图路由：结构化输出、多意图识别、白名单校验、超时/失败回退到现有确定性路由 | 未配置时行为不变；无效/越权意图被拒绝；回归集证明多意图识别改善且未知问题不会继承旧答案 |
| 2 | 问题规范化与会话上下文确认 | 指标、日期、维度、REALTIME/FINAL 来源可解释；不确定时澄清；新问题不误用旧上下文 |
| 3 | 异步任务可靠性 | 明确幂等、队列容量、取消语义、进程重启和过期结果；由本地线程池平滑迁移到持久队列设计 |
| 4 | 并行分支与汇总契约 | RAG/口径/血缘/字段/认证查询/探索分支独立状态；部分成功不丢失；口径、值、版本和引用一致 |
| 5 | 查询与数据发布安全门 | 身份在每次工具调用复核；固定模板、ACL、SQL AST、数据范围、结果上限、审计失败拒绝发布；FINAL 有可验证发布状态 |
| 6 | 可观测性 | request/trace/span 关联，分支耗时与错误码、检索证据、请求/响应模型 ID 与可用的后端指纹可追踪；缺失或非不可变版本显式说明，不记录原始敏感内容或权限凭证 |
| 7 | 生产化依赖适配 | 企业 SSO、持久任务队列、共享 checkpoint/状态库、密钥管理、部署与恢复流程；每项有本地可运行替代或清晰接口 |
| 8 | 评测、压测、故障演练与发布验收 | 意图、检索、答案忠实度、权限拒绝、批流对账、恢复及资源边界均有自动化验收门槛 |

## 执行规则

1. 每阶段先补失败测试，再实现，再跑相关测试与完整测试套件。
2. 每个阶段分别记录已完成、未完成、证据和风险，不把路线图节点冒充运行状态。
3. 外部模型、企业身份源、真实业务数据及外部工单等需要额外配置/授权的依赖，先保留可测试接口和安全降级；不伪造已接通状态。
4. 所有数值、认证口径和血缘必须绑定同一认证指标版本；探索结果保持显著 `NON_CERTIFIED`。

## 进度

- 总体：6/8 个功能阶段完成（本地开发验收口径）；阶段 1–6 已完成，阶段 7 待开始。
- 阶段 1 完成证据：配置真实 Key 后完成合成问句 API 烟测及 24 条合成集在线对比；在线路由较本地规则基线 exact match 提高 16.7 个百分点，模型失败回退、结构校验、多意图与越界拒绝均有自动化测试；全量测试 112 项通过。DeepSeek 只提供白名单意图建议，默认关闭；异步任务在后台识别并更新计划意图，不会为即时返回 request_id 而同步等待模型。`.env` 权限已收紧为仅当前用户读写。
- 验收边界：24 条是开发/回归集，不是独立盲测或业务专家验收；小样本 100% 不代表线上准确率。真实业务流量启用前，仍需脱敏真实问句评测、供应商与敏感数据合规审查、超时/熔断监控及成本预算。
- 新增 Q-A 开发题集：50 条，简单/中等/困难为 20/20/10；覆盖 8 项能力与 7 类边界场景，含标准答案和证据定位。结构测试通过；这仍是评测资产建设，不代表已完成答案质量评估。见 `docs/evaluation/qa-evaluation-set.md`。
- 阶段 2 完成证据：明确指标新问题从空任务状态开始，不继承旧指标、日期、REALTIME/FINAL 状态或维度；仅对确定性短追问（按产品、指定新日期、口径、血缘、实时/正式）继承必要任务上下文；含糊的“那呢”及冲突状态改为澄清。拒答后清空旧会话上下文；追问路由不调用 LLM 猜测，工具层仍逐次校验权限。同步与异步 API 均有回归测试。
- 阶段 3 完成证据：恢复任务使用数据库条件状态更新，避免并发请求重复认领；提交接口支持按用户隔离的 `Idempotency-Key`，同键同请求返回原任务，同键不同请求返回 409，并发重试只创建一个任务；容量限制同时计入数据库活跃状态与取消后仍在运行的线程；取消运行中任务不得发布迟到结果。新增用例覆盖上述边界、重启恢复及两级过期。通过 `.venv/bin/python -m pytest` 执行全量测试，134 项通过（既有 Starlette 弃用警告）。状态语义和持久队列迁移契约见 `async-task-reliability.md`。
- 阶段 3 保留边界：本地线程池与内存结果不跨进程共享；取消不能中断已运行的同步工具；重启恢复需用户重新提交问题并完整重跑。跨进程共享状态、加密任务载荷、租约与持久队列属于阶段 7，当前不得将多个 API 实例连到同一 SQLite 任务表。
- 阶段 4 完成证据：分支异常只将对应分项标为 `unavailable`，不丢失其他成功分项；汇总前校验认证指标引用和检索片段的版本、更新时间，冲突分项不发布数值、SQL 或引用；最终分项状态回写异步进度。多轮会话只继承经汇总认可的任务状态，新指标分支失败不会恢复上一指标。全量测试 138 项通过（既有 Starlette 弃用警告），Ruff 检查通过。契约与适用边界见 `parallel-branch-contract.md`。
- 阶段 5 完成证据：认证信贷指标仅查询信贷域，用户同时拥有其他域权限也不能扩大该指标 SQL 与来源引用范围；FINAL 查询在读取缓存或数值前复核对应批次 `FINAL` 状态和六项质量检查，撤回发布状态或缺失质量检查时返回 `unavailable`，不发布数值、SQL 和引用。固定 SQL 模板、SQLGlot AST 校验、只读执行、93 日/500 行上限、逐次授权和审计失败拒绝发布继续由现有链路约束。全量测试 141 项通过（既有 Starlette 弃用警告），Ruff 检查通过。契约与边界见 `query-publication-gate.md`。
- 阶段 6 完成证据：普通/异步问答、静态缓存命中、认证结构化查询、问句式和结构化探索均写入脱敏 Trace；异步 `request_id` 与 `trace_id` 关联，记录总耗时、分支耗时、固定状态错误码、认证引用 ID。`router_mode` 区分本次模型成功、失败回退、会话规则、缓存命中与结构化入口；`retrieval_mode` 取实际检索 backend，多意图分支 span 各自保留。DeepSeek 成功响应时单独记录请求模型 ID、响应 `model` 和 `system_fingerprint`；回退或响应缺失时对应值为 `null`，不从共享路由器状态推断。证据 ID 与运行元数据按字符/长度白名单过滤；新 Trace 写入时清理 30 天前的 span，不清理必需审计。`GET /v1/traces/{trace_id}` 通过审计表校验归属后返回，不存原始问题、SQL、查询结果、用户 ID 或权限凭证。全量 156 项测试通过（既有 Starlette 弃用警告），Ruff 检查通过。字段契约见 `observability-contract.md`。
- 阶段 6 保留边界：DeepSeek 官方定义 `system_fingerprint` 为后端配置指纹，它不等于不可变模型权重/发布版本；本轮只用本地模拟响应验证了字段链路，没有新增真实外部调用。Trace 写入仍尽力而为，审计写入仍强制失败关闭；单机 SQLite 追踪不等于生产级 OpenTelemetry/跨服务 span。
- 阶段 7 进展：已有 OIDC JWT 身份校验适配器、Redis 会话/响应缓存适配器和 `/livez`、`/healthz`、`/readyz` 探针。本轮新增部署 profile 启动校验：本地 SQLite/线程池只允许单 worker、单实例；`production` profile 在持久共享任务队列与共享 checkpoint/结果存储落地前 fail closed；`start_demo.sh` 显式传递 worker 配置。新增部署配置测试覆盖多 worker、多实例、非法配置及生产 profile 阻断。定向测试 19 项通过（既有 Starlette 弃用警告）。
- 阶段 7 新增：`/readyz` 除审计数据库和配置的主检索外，也会检查已配置的会话记忆依赖；Redis 会话记忆通过 `PING` 探测。响应缓存是 best-effort，仍不作为 readiness 硬依赖，避免缓存故障造成不必要的停流。新测试先复现 Redis 会话记忆失联时错误返回 200，再验证返回 503；缓存不可用仍返回 ready。全量测试 176 项通过，Ruff 检查通过（仅既有 Starlette 弃用警告）。
- 阶段 7 新增安全前置：新增 AES-256-GCM 异步任务载荷加密组件，随机 nonce、`request_id`/key id 认证绑定、密钥轮换解密能力及 64 KiB 上限；密文篡改、跨任务换绑、未知 key 都拒绝。现有 Compose Redis 关闭持久化且采用 `allkeys-lru`，因此明确不用于任务队列。该加密组件尚未接入任务管理器，key 注入/KMS 和持久共享队列/状态/结果存储仍未实现；production 继续 fail closed。阶段 7 新增队列 transport 后，全量测试 182 项通过，Ruff 检查通过（仅既有 Starlette 弃用警告）。
- 阶段 7 新增基础设施与队列原语：加入需显式启用的隔离 `task-redis` profile，独立卷、仅本机 6390、AOF `appendfsync always`、256 MiB `noeviction`、自动重启；既有 64 MiB `allkeys-lru` cache Redis 未改。Compose 配置校验通过；容器已启动为 healthy，配置实读正确，带 TTL smoke key 经容器重启后保留并已清理。新增 `RedisTaskQueue`，只把 request_id 和 AES-GCM 密文写入 Stream，支持 consumer group claim/ack 和 `XAUTOCLAIM` 恢复；本机真实 Redis 集成测试验证上述行为。尚未接入 `QuestionTaskManager`/HTTP，且共享状态/checkpoint/结果、提交幂等/容量/lease、ACL/TLS/KMS 仍未实现，production 继续 fail closed。
- 阶段 7 未完成项：持久共享任务队列、共享 checkpoint/结果存储、密钥托管/KMS、真实企业 IdP 配置与跨进程恢复演练仍未接入；Redis 当前只用于记忆/缓存，不是任务队列或任务状态库。生产 profile 拒绝启动是安全保护，不代表生产部署已具备。
- 下一步：阶段 7 继续实现可替换的共享队列与 checkpoint/结果存储适配并完成跨进程演练；其后阶段 8 执行 Q-A 50 条评测、检索/ACL/引用质量门槛、压测与故障演练。报告生成保持在独立 Agent 范围外。
