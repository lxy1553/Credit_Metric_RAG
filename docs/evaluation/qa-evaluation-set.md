# 问答质量评测集

正式题集位于 [`credit/data/qa_evaluation.json`](../../credit/data/qa_evaluation.json)，共 50 条本地合成/知识目录用例。它与 `intent_evaluation.json` 的意图分类开发集用途不同：本题集检查完整回答应如何作答、澄清或拒答，后续可供检索评估、答案评估和人工验收使用。

## 用例字段

| 字段 | 含义 |
|---|---|
| `id` | 稳定用例编号：S=简单、M=中等、H=困难 |
| `question` | 用户问句；金额计算题中数字由问题明确给出 |
| `standard_answer` | 人工编写的目标答案，包括必要的拒答/澄清行为 |
| `evidence_sources` | 证据文件及 JSONPath/说明性定位；`question_constraints` 表示题目显式给定的数值 |
| `capability_labels` | 能力标签，可多选 |
| `intent_labels` | 系统应触发的处理意图，可多选 |
| `difficulty` | `simple`、`medium` 或 `hard` |
| `boundary_labels` | 边界标签，可多选；没有边界时为空数组 |
| `expected_action` | `answer`、`clarify` 或 `refuse` |
| `conversation_context` / `context_expectation` | 可选多轮上下文及该用例应如何继承或清空上下文的期望 |

## 难度与能力覆盖

| 难度 | 数量 | 比例 |
|---|---:|---:|
| 简单 | 20 | 40% |
| 中等 | 20 | 40% |
| 困难 | 10 | 20% |

能力标签覆盖事实查询、口径解释、血缘追溯、多跳推理、对比分析、计算推理、模糊查询与拒答。边界标签覆盖无答案、版本冲突、权限边界、口语化、多意图混合、否定条件和时间歧义。每条可有多个能力或边界标签，因此边界数不等于用例总数。

## 当前证据与限制

- 认证指标口径和指标血缘以 `credit/data/catalog.json` 为准，当前目录版本为 `demo-v2`。
- 物理表结构以 `credit/data/schema_catalog.json` 的整理结果为准：光大信托基础层 v1.9 是统一规范，东华数据字典 2021-06-10 是来源结构。
- 项目本地合成数据覆盖 2025-07 至 2026-06 共 12 个月的月末快照，另保留 2026-03-01/02；它不是逐日完整数据。问到未提供的具体日期、目录中没有的指标或权限不足内容时，标准行为是说明缺失、澄清或拒答，不能用旧答案续答或用通用行业概念冒充认证事实。
- 计算题把数字直接写在问句中，答案依据题内数字和认证表达式，可以独立手算核验；这类结果是演算题答案，不表示演示数据库实际查询值。
- 含 `conversation_context` 的用例用于阶段二会话状态回归：只有明确、省略主语的追问可继承当前指标；新指标、相对日期、来源状态冲突或不明确追问必须清空/澄清相应上下文。会话上下文不能代替服务端每次重新校验身份与权限。
- 题集是开发/回归集，不是盲测集；`standard_answer` 和证据都与本项目当前知识源绑定，目录或权限规则升级后应复核版本冲突案例并更新题集版本。

## 校验

运行以下命令检查条数、20/20/10 难度分布、能力与边界覆盖、用例必填字段和证据文件存在性：

```bash
.venv/bin/python -m pytest tests/test_qa_evaluation_set.py -q
```

此校验验证题集结构与标注契约，不会运行系统回答。端到端规则评测的运行方式见下节。

## 可执行回归评测

运行器会从本地合成数据启动隔离的 `QuestionService`，逐题使用 sidecar 规则检查关键事实组、意图、回答/澄清/拒答动作、引用版本和权限边界。显式 `conversation_context` 会按 user turn 回放；每题使用独立会话，避免用例间记忆污染。默认关闭 LLM 路由，结果可复现且不产生模型调用费用。

```bash
.venv/bin/python -m credit.qa_evaluation
# 或
.venv/bin/credit-qa-eval
```

用例级事实检查在 [`credit/data/qa_evaluation_rubrics.json`](../../credit/data/qa_evaluation_rubrics.json)，评测摘要和失败案例会写到 `var/qa-evaluation-local.json`。报告只记录 case ID、通过状态、错误类别与缺失规则组，不保留问题、答案、SQL、查询行或异常文本。版本摘要包含题集和 rubric 的 SHA-256，便于比较运行结果。

该规则执行器不是完整的 RAG 生成评测：它不会判断同义表达的语义正确度，也没有 claim-level grounding、表达质量、逻辑质量或人工/Judge 一致性评分。应先用它定位确定性安全和覆盖缺口，再以人工标注样本校准 LLM Judge；不可把规则通过率当作线上准确率。

2026-10-14 本地基线：50 题中 6 题通过全部规则。剩余失败主要来自题集要求但当前确定性意图路由尚未覆盖的通用项目目录问答、比较和给定数字演算，以及部分复杂多意图/拒答场景。最近一次修复让显式否定数值查询只走口径解释，S18 通过。逐题错误类别见 `var/qa-evaluation-local.json`；这些失败是待建功能，不应用降低事实或安全规则的方式消除。

2026-10-22 路由修复后的本地结果：50 题中 9 题通过全部规则。S09 和 S10 现在分别按题目给定申请笔数和金额计算，返回认证公式版本引用，不执行数仓 SQL；其意图标签从 `query + definition` 改为独立的 `calculation`。其他 41 题仍未通过各自完整规则，不能把这次意图开发集的 29/29 误解为端到端问答准确率。
